# 学习路径（数据结构 → AI 应用开发）

> 定位：双非本科 + 已有数据结构基础。目标不是"学完所有课"，而是用项目和
> 面试反馈倒逼学习，每两周有一个可展示的产出。

## 已完成（本项目覆盖的能力）

| 能力 | 对应项目产出 |
| --- | --- |
| Python 工程能力 | 类型注解、模块拆分、协议抽象、pytest |
| Web 服务 | FastAPI 路由、校验、错误码、OpenAPI |
| 数据库 | SQLite 表设计、迁移回填、事务 |
| RAG 概念 | 切分、Embedding、Top-K、引用溯源 |
| 评测意识 | Recall@K / MRR / 延迟，用数据说话 |
| 部署 | Docker Compose、健康检查、数据持久化 |

## 接下来 8 周：按面试优先级补基础

**第 1-2 周：Python 与数据库**

- Python：迭代器/生成器、装饰器、上下文管理器、常用内置库
- SQL：多表 JOIN、索引原理（B+ 树）、事务隔离级别
- 产出：把 EvidenceQA 的 repository 层重写一遍，要求去掉 ORM 痕迹也能讲清 SQL

**第 3-4 周：计算机基础**

- 网络：HTTP/1.1 与 HTTPS、TCP 三次握手、DNS、鉴权（JWT / OAuth）
- 操作系统：进程线程协程、文件系统、虚拟内存（够面试深度即可）
- 产出：给 /ask 加一个简单的 API Key 鉴权 + 限流，写进 README

**第 5-6 周：检索进阶**

- 真实 Embedding（BGE-M3 本地跑通）、向量索引（FAISS 或 sqlite-vec）
- BM25 混合检索、重排（rerank）概念
- 产出：EvidenceQA 接 BGE + 混合检索，用现有 20 题评测集对比前后指标

**第 7-8 周：生产化与补缺**

- Docker 多阶段构建、Gunicorn 多进程、日志与监控
- 异步任务（上传大文档走队列）、缓存（Redis 或本地缓存）
- 产出：给项目加异步文档处理 + 一个监控端点（/metrics 或日志结构化）

## 不建议现在学（时间性价比低）

- 微服务全家桶（K8s、Service Mesh）：中小厂面试很少深挖
- 大数据组件（Spark / Flink）：与 AI 应用开发岗位相关性低
- 死磕算法竞赛难度：保持 LeetCode 高频题 150 道的手感即可

## 简历与面试策略（双非背景）

1. **用指标代替形容词**："完成 RAG 系统" → "Recall@K=1.0，18 测试全绿，
   一键 Docker 部署"
2. **准备一个 5 分钟现场演示**（见 03-demo-script.md），比任何描述都有说服力
3. **主动讲失败与取舍**：为什么先不用云端 Embedding、为什么评测先行——
   面试官要的是思考过程，不是完美答案
4. **海投 + 面试复盘**：把面试中被问住的问题记下来，每周补一个短板，
   投递优先级：AI 应用 / 后端开发岗位
