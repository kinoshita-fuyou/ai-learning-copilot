# 5 分钟面试演示脚本

> 原则：先讲清"为什么做"，再演示"能做什么"，最后用指标收尾。演示中主动
> 指出设计决策，面试官会顺着追问，这比展示功能本身更值钱。

## 准备（面试前）

```bash
cd ~/Documents/Codex/2026-06-14/ai/evidenceqa
./scripts/demo.sh
```

脚本会重建演示库（3 份文档）、启动服务并打开浏览器。确认：

- `http://127.0.0.1:8001` 四个页签都能打开
- 文档库里有 3 份文档（demo_policy / demo_product_manual / demo_engineering_guide）
- 网络断开也能跑（全离线）
- `demo.sh` 默认用离线模板回答（`EVIDENCEQA_ANSWER_PROVIDER=template`），
  不受机器上残留的 API Key 影响

## 第 1 分钟：开场（不用打开电脑）

> 我做了一个可溯源的企业知识库问答系统。核心不是聊天，而是"回答必须能回到
> 原文"：文档上传后自动切分和向量化，提问时先检索相关片段，再生成回答并附上
> 引用来源。选这个方向是因为它的质量可以量化——我用 Recall@K 和 MRR 评测检索，
> 而不是凭感觉说"效果不错"。

## 第 2 分钟：文档库演示

1. 打开「文档库」页签，展示已有 3 份文档（制度 / 产品手册 / 研发规范）。
2. 拖入 `data/demo_policy.md`（已在库中可先删除再传，展示上传交互）。
3. 讲一句：> 上传时有四重校验——类型、编码、空文件、大小。切分按段落优先，
   chunk 保留字符范围，所以引用能精确到原文位置。
4. 可顺手在 `/docs` 看自动生成的接口文档，证明"接口先行、前后端分离"。

## 第 3 分钟：问答演示

1. 切到「问答」页签，问：**"远程办公需要提前多久申请？"**
2. 展示回答 + 引用来源卡片（标题、相似度、片段、字符范围）。
3. 讲一句：> 回答和引用来自同一批检索结果，用户能逐条回到原文核对，这是
   防幻觉的第一道防线；检索为空时系统会明确说"未找到"，不硬编。
4. 换一个跨文档问题（如 "P0 故障多久内响应"），说明多文档检索。

## 第 4 分钟：检索与评测演示

1. 切到「检索」页签，输入"发票报销期限"，展示 Top-K 相关度排序；补充一句：
   默认是 BM25 + 向量混合检索，纯向量模式可以用 `hybrid=false` 对比。
2. 切到「评测」页签，点"运行内置评测集"（默认混合检索模式）。
3. 讲一句：> 21 道题覆盖 3 份文档，混合检索 Recall@K = 1.0、MRR = 1.0；
   纯向量基线 MRR 是 0.9683，混合检索把一道关键词型问题从第 3 名提到第 1 名。
   说明口径：本地特征哈希 + BM25 + 小语料，这是基线；换真实 Embedding 后我会
   用同一套评测集重测，保证改动可量化。

## 第 5 分钟：技术亮点与收尾

背熟三个亮点，等追问：

1. **Embedding 可替换**：本地特征哈希只是实现，接口与云端一致，换 BGE /
   OpenAI 只改一个 Provider 类。
2. **评测先行**：先有 Recall@K / MRR，再做任何检索改动都有依据。
3. **工程闭环**：32 个自动化测试 + GitHub Actions CI + Docker 一键部署 +
   断网可演示。

> 如果面试官问"还能做什么"，用 Q17 的改进优先级回答，展示规划能力。

## 常见翻车点

- 忘记先跑 `demo.sh`，现场才装依赖 → 提前一天演练
- 问"数据量大了怎么办"只会说"换向量库" → 补一句：先建评测基线，再换索引，
  用同一评测集对比召回和延迟
- 被问 embedding 原理答不上 → 复习特征哈希：token 化 → 哈希映射 → 归一化，
  以及它和语义向量的差距
